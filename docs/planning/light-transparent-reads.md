# Internal light transparent reads

`src/clients/light-transparent-reads.ts` composes the frozen argument/result shapes for `getAddressUtxos` and `getAddressBalance`. Its module exports are internal test/composition entrypoints only: no root exports, factory, Network, initialization, acquisition or wallet integration. Caller supplies accepted initialized transparent-address and lightwire instances, a CustomLightTransport, and the private native encoding family main/test/regtest. Family is not chain identity.

Every address is passed unchanged to the accepted native decoder; no JS encoding inference, normalization, UA extraction or TEX conversion. Input is an ordinary data record with a dense array of 1–100 tokens. Test/regtest shared encoding is retained. Response addresses must occur in the admitted request and decode in the same family. Duplicate returned outpoints are malformed.

Both calls are unary, once only. GetAddressUtxos explicitly sends start_height `"0"`, max_entries `1001`; at most 1000 entries succeed. Reaching the extra entry fails RESOURCE_LIMIT, preserving completeness without implicit unlimited requests or speculative height pagination. This local budget is an adapter policy, not a server maximum. Successful empty lists and zero balances remain success. Response byte limit is 4 MiB, matching the accepted codec. Owned transport signals are aborted and dependent listeners detached on every exit.

`value_zat` is the native lightwire decimal int64 DTO, admitted as 0 through 9223372036854775807 and converted directly to bigint. This read contract reports wire balances, not a consensus spendability or MAX_MONEY proof. Negative int32 indices fail; heights must fit uint32, including genuine height zero (no invented sentinel). Scripts are independently allocated. ReplyList carries no checked chain point: `tip: null` means unavailable metadata, not absent UTXOs. No confirmations or identity are fabricated.
