# Recovery amendment acceptance and evidence

This page records the original D26 specification amendment and its required recovery matrix. Current implementation and source-bound Node/Firefox evidence are recorded in [wallet payment qualification](wallet-payments-qualification.md); the historical checks below are not the current runtime acceptance status. D26 itself was a **specification amendment**. The [normative recovery contract](../api/operations.md), [declarations](../api/public-api.md), [H1 host contract](../api/host-contract.md) and [source mapping](../api/host-mapping.md) define required behavior. No runtime fixture, mock wallet, live provider or real transaction is supplied here.

## Compile-only checks in this amendment

`docs/api/examples/recovery-policy.ts` has positive cases for default, offline and bounded online opening without an application operation-ID store or signer, and typed startup completion/deferred reporting. Negative cases reject offline rebroadcast, unbounded online policy/retries, first-dispatch startup policy, secret/operation-ID factory inputs, `getJobID`, and resume-as-dispatch. Numeric positivity, runtime route presence/identity, actual pagination and durability cannot be proved by these types.

Test-first evidence: before changing declarations, `npm run docs:typecheck` exited **2**, rejecting missing `RecoveryPolicy`/`RecoveryReport`, `WalletOptions.recovery` and `WalletClient.recovery`. This is a declaration mismatch demonstration, not a failing recovery runtime test. After amendment the same cases compile. `npm run docs:check-recovery` checks the positive suite and removes the negative assertions in an external temporary copy to verify every forbidden case produces its expected compiler diagnostic code at its assertion location; it also checks active examples do not require save/load operation-ID helpers and that the package stays private. Review-fix test-first sabotage replaced the missing resume selector with an unrelated string/number assignment error at the same location: the old location-only checker passed (exit 0); the strengthened checker rejected TS2322 in place of expected TS2345 (exit 1). The original assertion was restored before validation. This tests the compile-only checker, not SDK runtime behavior. Full command logs are retained outside the tracked tree by the implementer/coordinator.

## Required real acceptance matrix

Restore applicability (#123): this version has no public database backup/restore/import operation. The supported-explicit-restore branches of R07/R16 are therefore not applicable, rather than passed restore tests. Application-controlled copies/rollback retain the R12 limitation; ordinary open cannot detect them or invalidate their consent automatically. See [backup and restore scope](../api/wallet-runtime.md#backup-and-restore-scope). Mnemonic account import is not a database restore.

Use deterministic synthetic databases, protocol responses and failure injection against the **real** wallet engine/host transport boundary, never a mock implementation presented as SDK evidence. Run durability cases independently on Node filesystem and browser OPFS, with actual worker/module destruction. Pin coherent Common 1.0.0 graph, schema, runtime assets, network/branch fixtures and protocol revisions. Fixtures are not permission for live requests, funds or deployments.

## Remaining qualification decisions and exclusions

The amendment fixes API behavior and retains `operations.resume`; it does not rename the namespace or settle binary/storage schemas. Before runtime delivery, pin consent/route/custom-adapter identity encoding, internal paging/checkpoint and provenance migration schemas, clock trust mechanism, exact valid extension transaction compositions, real VFS journal/flush policy, transport confirmation/expiry/reorg evidence rules and manifest engine/control-envelope limits. H1 advances to `zcash-host/1.0-draft.2` because opening and attempt-start semantics change; exact-revision negotiation must reject incompatible peers. This amendment did not supply an implemented peer or migration evidence; consult the current qualification records above.

G0–G6 and F1–F8 remain unpassed by these checks. No protocol vectors, cryptography, SQLite durability, WASM liveness, provider behavior, device support, performance or privacy audit result is claimed. Existing settled pool/account/signer scope and deferred #10–12 remain unchanged. The package now contains a private SDK implementation. Publication, deployment, license selection and live blockchain activity remain excluded.
