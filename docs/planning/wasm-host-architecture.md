# WASM host architecture

Authoritative planning integration, 2026-09-04. Implements the owner's D07 refinement on paper: **start WASM-first in Node and browser**, with one public TypeScript API, a non-shared baseline and a separately built threaded shared-memory artifact. No N-API shipment promise. Bundled SQLite lives **inside the wallet WASM module** in both runtimes: Node filesystem VFS, browser OPFS VFS. This supersedes earlier “native SQLite on Node” defaults while retaining Rust-owned Zakura storage. Native/N-API acceleration is benchmark-triggered future work only.

[Decision log](decision-log.md), [transaction/query plan](transaction-query-api.md), [keys plan](keys-accounts-signers-api.md) and [workplan](api-surface-workplan.md) govern scope. Three local scratch audits—WASM architecture, transaction automation, and wallet query/sync—were integrated as source/design evidence; their temporary files are not repository dependencies or durable links. No builds, instantiation, runtime tests or benchmarks were run in this integration.

## Runtime and database ownership

| Runtime | Baseline | Threaded qualification |
| --- | --- | --- |
| Node | Dedicated `node:worker_threads` wallet owner from the baseline onward; non-shared WASM with bundled SQLite and synchronous host filesystem VFS callbacks. Bounded independent compute workers where operations are separable. | Qualify shared module/memory plus a Node Worker/parentPort Rayon bootstrap, allocator/TLS/stacks and readiness protocol. Browser helper globals are not a drop-in Node adapter. No COOP/COEP requirement in Node. |
| Browser | Dedicated worker, non-shared WASM and a no-SAB OPFS VFS path; transferable batches. | Secure context, `crossOriginIsolated`, SAB and WASM thread availability **and successful bootstrap** select the separately built fast path. Otherwise select the baseline worker artifact. |

A single wallet owner serializes **all SQLite calls** and mutations (including scans, trees/nullifiers, proposals/locks, addresses, account changes, status, outbox and migrations). Queue coherent reads too. Enforce one writer per database across tabs/processes by coordination or explicit rejection of a second opener; one JS object's queue is insufficient. With a `SQLITE_THREADSAFE=0` library instance, serialize even calls on different connections. Mutex configuration cannot be upgraded by adding WASM atomics.

Register each VFS in the **same bundled SQLite instance/memory** used by rusqlite. Use `WalletDb::from_connection` after loading rusqlite's array module. `BlockDb::from_connection` is private: qualify the default VFS or use a bounded in-memory `BlockSource` adapter. A separate JS SQLite module cannot lend rusqlite a pointer across instances.

Node VFS must implement filesystem open/close/delete/access, reads/writes/truncate, flush/durability, locking and error semantics via worker-local host imports. `wasm32-unknown-unknown` supplies none automatically. Browser VFS must implement the equivalent synchronous SQLite file contract. Pre-opened OPFS synchronous access handles in a dedicated worker are a no-SAB candidate; SQLite's SAH-pool examples are not an installed rusqlite adapter. WAL/concurrent-reader assumptions must be qualified for this exact VFS. No IndexedDB or ephemeral fallback silently replaces durable storage. Explicit memory-only mode is labeled ephemeral and lacks restart guarantees.

External schema/migration ownership and outbox atomicity follow the transaction plan's `transactionally_with_extension`/external-migration design. Database transactions must preserve scan height, notes/spends, trees/witnesses, locks and operation bytes together as applicable. Do not retain transactions or mutable Rust borrows while awaiting network, device or arbitrary JS callbacks.

Crypto can parallelize without parallel database mutation. Fetch the next bounded block batch while scanning the current batch; reconcile and commit in chain order. Fused local `create_proposed_transactions` stays serialized with wallet mutations, even if internal proving uses Rayon. Detachable PCZT/proof work may overlap scanning only at supported immutable artifact seams with revalidation before final storage. Begin with one admitted proof and bounded queues under an application-wide CPU/memory budget; measurements may later justify more concurrency.

Host imports are narrowly entropy, clock, VFS file operations, job/progress scheduling and integrity-checked asset delivery. Network fetch/stream/auth/retry and external signer callbacks belong in TS, outside borrowed Rust transactions. Do not export internal cryptographic gadgets or per-note callbacks. Tiny codecs may use a lightweight independent instance; public queries must not eagerly load wallet/prover assets.

Handle table keys include instance/session, kind, slot and generation. Only the owning worker dereferences them; reject wrong-owner, stale, wrong-kind and repeated raw handle-release calls. Public close/dispose wrappers remain idempotent and must not forward a second release. Wallet owns database/scanner/proposals/artifact associations; a job owns immutable inputs and leases on assets; the caller owns created memory signers and may attach them independently. Close drains/rejects queued work, closes storage, ends leases and invalidates wallet-dependent handles, without disposing shared injected signers. Restart rehydrates stable IDs/versioned artifacts, never pointers. Finalizers are leak backstops, not the correctness mechanism.

## Buffers, jobs and cancellation

Small control records use structured data; payloads use binary batches/`Uint8Array`, exact bigint amounts and validated integer widths. Avoid per-note RPC or JSON/base64/hex internally. Keep adjacent Rust proposal/PCZT stages in memory without repeated parse/serialize. This is a boundary design, not a measured speedup.

| Boundary | Contract |
| --- | --- |
| Caller → baseline worker → WASM | Default API preserves caller buffers by copying. An explicit consuming internal path transfers a standalone owned ArrayBuffer, then normally copies once into linear memory; transfer is not arbitrary zero-copy placement in WASM. |
| WASM → caller | Copy into an owned standalone buffer, then transfer; never detach module memory or expose a wallet heap containing secrets. Honor offsets/lengths; do not transfer pooled Node Buffer backing stores. |
| Trusted owner worker ↔ WASM | Internal checked `(allocation,offset,length,generation)` lease for synchronous fill/read, explicit consume/release, bounds/alignment/alias checks. No free/reallocate/reentrant mutation or retained borrow across await while leased. |
| Shared compute domain | Same compatible shared linear memory plus ownership descriptors; arbitrary SAB is not a Rust allocation. Synchronize access/growth; no serialization of shared proving keys between pool threads. |
| Independent baseline instances | Compiled module code may be shared/cloned; Rust objects/handles/heaps cannot. Transfer serialized owned job inputs; account for duplicated assets and heaps. |

Generated array bindings do not guarantee zero-copy. Unshared memory growth detaches prior views, while old shared views retain their old extent; refresh views after allocation/growth and coordinate leases. Pre-size bounded arenas, retain parameter/proving keys by verified digest/circuit/version/context, and bound queued bytes/jobs. Disposal/zeroization is best effort across JS copies/GC/crashes, not secure-enclave isolation.

Promise completion is not scheduling. Heavy synchronous exports run off the UI/event loop. Cancel queued jobs before start and fetches where supported; running scan/proof cancellation is cooperative at actual boundaries. Worker messages cannot interrupt an occupied synchronous export. SAB flags help only if Rust polls them. Baseline scanning yields between bounded batches; monolithic proving may finish before cancellation acknowledgment, or an isolated disposable prover domain can be discarded. Never routinely terminate the wallet worker to cancel a payment, or kill one Rayon worker and continue potentially locked shared state. Pool crash invalidates that compute domain. Distinguish requested cancellation, pre-commit cancellation, completion and unknown side effect; observer abort does not undo broadcast.

## Threading and scanner liveness

`multicore` selects dependency/code paths; it does not spawn host workers. Threaded WASM needs atomics, compatible shared/imported memory with a declared maximum, TLS/stacks/allocator initialization and a qualified pool bootstrap. `bulk-memory` is part of the adapter toolchain recipe; `mutable-globals` is not a threading switch. SIMD `simd128` is independent and optional; unsupported module instructions/imports can reject instantiation before any JS branch. One threaded binary cannot change its shared-memory requirement into a no-SAB fallback at runtime.

Use a pinned toolchain compatible with Zakura's MSRV and the chosen adapter; qualify the applicable `wasm-bindgen-rayon` std-rebuild/target-feature/TLS recipe and matching C objects. The report's adapter documentation is moving guidance, not a pinned integration guarantee. Initialize and await pool readiness **before any Rayon-using export**, including scanner/lazy initialization; one cached initialization promise per compute domain, bounded positive worker count and startup timeout. Node bootstrap must qualify `Worker`/`parentPort` against the same shared memory/runtime protocol; `--target nodejs` alone supplies none of this.

The backend scanner unconditionally uses Rayon/flume even when crypto multicore defaults are off. The audit traces batch work dispatched to Rayon followed by blocking channel collection; an unthreaded module can fail to spawn or stall waiting for unscheduled work. Moving that module into a browser/Node worker does not fix intra-module liveness. This is a **source-derived risk**, not a reproduced runtime failure.

Required baseline gate: exercise actual compact scanning through completion on non-shared Node and no-SAB browser. Investigate B `scanning::scan_block` ([source](https://github.com/zakura-core/wallet-libraries/blob/a9142ee100b3a563b7d9ba7a8e94201d00ad8154/librustzcash/zcash_client_backend/src/scanning.rs#L770)) without batch runners plus public wallet writes/metadata as a serial seam. It is not yet a validated equivalent of `scan_cached_blocks`: preserve nullifiers, prior metadata, tree sizes, checkpoints, continuity/reorg and atomic `put_blocks`. If public seams cannot implement correct serial ingestion, record a minimal upstream scheduler/serial API change with a failing probe under D01. No such production patch is authorized here. Threaded scanner must separately prove readiness, worker execution and bounded completion.

Browser fast path checks secure context, isolation in the relevant window/worker, SAB availability, WASM thread feature support and actual worker bootstrap. Typical deployment uses COOP `same-origin` and COEP `require-corp` (or supported `credentialless`), compatible Permissions Policy and CORS/CORP for cross-origin worker/module/parameter assets. The SDK cannot set embedding-page headers. Qualify popups/iframes, CSP and asset origins. Missing prerequisites select baseline before incompatible module load. Failed partial bootstrap is cleaned up before a fresh fallback instance; expose a diagnostic reason. This is declared startup artifact selection, not silent provider/storage/security failover or replay of a failed mutation.

## Packaging

One npm product and TS API; two WASM builds with Node/browser-specific loaders, VFS and worker entries. The two runtimes may share each binary only if the import ABI is qualified; no promise of four distinct crypto binaries or a universal binary. Browser ESM/explicit initialization and Node conditional exports must keep Node imports and eager SAB access out of browser/SSR/query-only imports. Issue #1 freezes `WasmArtifact` as a manifest URL plus expected manifest SHA-256. The canonical typed manifest binds contract/ABI/schema, build/locked dependency graph, mode and all executable module/glue/WASM/worker/thread-bootstrap assets with URL/hash/length/kind/media type. Verify the manifest, expected mode/versions and every executable asset before import/worker start and authority/storage; H1 expectations come from the verified manifest. [H1.1](../api/host-contract.md#h1-1-negotiation-before-authority) defines canonical encoding, credential-free URL confinement and verified-byte execution. Lazy-load verified Sapling spend/output assets (47,958,396 and 3,592,860 raw bytes in source; not peak memory) and circuit keys from application bytes or configured third-party sources; no project CDN. No Sprout assets by default.

Qualify actual Vite/Webpack output and direct browser ESM if offered: worker URLs, emitted glue/snippets, WASM MIME, CSP/CORS, module/parameter resolution, cache corruption and abort/retry. Supported Node/module-format claims require real package loading. Optional SIMD variants wait for justified engine requirements or the future benchmark issue.
