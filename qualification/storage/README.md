# Same-instance storage qualification

Disposable F3 experiment, not an SDK. Baseline policy: one admitted owner,
rollback journal `TRUNCATE`, `synchronous=FULL`, memory-only temporary tables,
no WAL, ATTACH, secondary database or concurrent reader. Every SQL operation
runs on the bundled rusqlite SQLite instance inside its dedicated worker.

Node uses actual synchronous filesystem operations and a Linux kernel `flock`
on a permanent namespace lock file (never unlink or steal it). The installed
`flock` helper acquires the lock through an inherited open file description;
the worker retains the descriptor. Browser acquisition awaits exclusive OPFS
sync access handles for the database and journal before entering SQLite.
SQLite lock callbacks validate that whole-owner lease. There is no timeout
that steals a live owner's lock. This policy covers cooperating owners of the
same dedicated namespace, not unrelated SQLite tools or external file mutation.

OPFS uses two fixed real files. A journal of length zero is logically absent;
its synchronous delete is truncate-to-zero plus flush, retaining the physical
slot. No database serialization, copies, in-memory filesystem, separate SQLite
module, shared memory or fake generated glue is involved.

The suite commits a synthetic fixture, closes SQLite, terminates the worker,
and verifies exact bytes in a fresh worker without recreating or seeding.
The same SQL, C adapter and generated WASM run in Node and OPFS workers.
Crash controls stop inside a synchronous import **after the actual file primitive**;
the external parent terminates the worker and creates a fresh one. The hot-journal
control observes SQLite's actual journal magic and recovery writes. Checkpoints
cover journal sync, database write, database sync and journal truncation.

`src/wallet.rs` additionally invokes the pinned wallet's real
`WalletDb::from_connection`, rusqlite array module, `WalletMigrator::init_or_migrate`
and `with_external_migrations`. It executes 66 built-in migrations on an empty
wallet; a deliberately failing external migration rolls back its table/data, and
a successful retry persists migration 67 and exact bytes across reopen. This
qualifies that external migration step, not atomicity of the entire migration DAG.
Its deterministic RNG is only for this empty synthetic wallet. It creates no
account, spending authority, funds, network request or live-chain state.

The `state` table's scan/tree/locked/outbox/epoch columns are representative SQL.
They do not establish actual wallet scan/tree/outbox consistency, revisions,
account fixtures, restoration, eviction or all F3 gates. Actual quota exhaustion
is **unexecuted**. `ENOSPC` and native `DOMException('…','QuotaExceededError')`
faults are explicitly injected; successful mapping is not real quota proof.

Source and allocator provenance:

- `runtime-provenance.json` identifies immutable `e73f423` runtime inputs. Only
  allocator, host-time and Rust allocation/pairing probes are derived from them.
  Evolving runtime/browser/scanner sources are never built by reference here.
- The runtime's complete Common 1.0 package graph remains identical, including
  package dependency edges; this crate adds direct root edges to already selected
  versions. The published wallet `.cargo_vcs_info.json` and consumed source files
  are checked against `a9142ee100b3a563b7d9ba7a8e94201d00ad8154`.
- Bundled SQLite is linked once with the C VFS. The 16 MiB static MEMSYS5 arena
  has canaries and stays below Rust's heap base. Runtime tests fill/exhaust/free
  SQLite allocations while a 24 MiB Rust allocation remains intact. Inspection
  rejects retained WASI libc allocator symbols/members and any memory growth
  owner beyond Rust dlmalloc. There are no WASI success stubs.
- `build.sh` preserves source, raw WASM, matching link map and genuine unedited
  wasm-bindgen 0.2.128 web output. Node imports that same genuine web-generated
  ESM bundle. `raw_exports()` proves the real generated instance bridge; the
  loader checks real externref initialization, imports and nonshared memory.

Reproduce using writable storage scratch and the already installed toolchain:

```sh
bash qualification/storage/build.sh /home/jack/zcash-storage-scratch/NEW-STAGE
STORAGE_BUNDLE=/home/jack/zcash-storage-scratch/NEW-STAGE/bundle timeout 150s node qualification/storage/run-node.mjs
STORAGE_BUNDLE=/home/jack/zcash-storage-scratch/NEW-STAGE/bundle timeout 60s node qualification/storage/run-process.mjs
timeout 10s node qualification/storage/test-error-mapping.mjs
timeout 10s node qualification/storage/test-serve-static.mjs
```

`env.sh` uses a separate copied Cargo cache, target and TMPDIR with jobs=2;
builds are offline and locked. `provenance.json` binds source, tool versions,
raw/generated bytes, map, inspection and feature graph. Raw/glue files remain
outside the repository. No generated source is patched or replaced.

Browser execution requires the coordinator's host because this worker sandbox
rejects localhost socket creation. The existing Firefox/geckodriver route needs
no security-policy changes. Do not attach to an existing coordinator session:

```sh
STORAGE_BUNDLE=/home/jack/zcash-storage-scratch/NEW-STAGE/bundle timeout --kill-after=10s 200s node qualification/storage/run-firefox.mjs
```

The runner creates its own loopback-only server and WebDriver session, requires
secure non-isolated no-SAB workers, records BiDi realm creation/destruction,
enforces 20s request and 180s whole-suite deadlines, and closes its session/server.
Its driver port defaults to 19445 (`STORAGE_DRIVER_PORT` may select a free port).
Before sending HTTP requests, the runner requires the spawned driver's own
listening announcement; a bind failure never probes or adopts the existing
endpoint. Shutdown joins bounded startup before deleting any returned session,
and checks cancellation before opening a socket, subscribing, or navigating.
Cleanup failures make an otherwise successful run exit nonzero; signal failure
codes are preserved. Driver readiness and socket opening each have a 10s bound.
`STORAGE_LOG_DIR` selects the output directory (which must already exist).

No-socket lifecycle regressions (all external effects simulated):

```sh
timeout --kill-after=2s 10s node --experimental-vm-modules qualification/storage/test-firefox-lifecycle.mjs
```

`run-browser.mjs` is the installed Chrome alternative; Chrome's current host
sandbox failure must not be bypassed with `--no-sandbox` or policy changes.

The Node process control executes a second OS process, observes fail-closed writer
contention, sends real `SIGKILL`, and verifies lock release plus hot-journal rollback.
Node executes `fsyncSync` on database/journal and directory descriptors. OPFS
executes actual sync-handle `flush()`. These are process/worker termination and
primitive execution results: no tested OS crash, filesystem guarantee across all
platforms, physical power loss, browser eviction or directory-durability claim is
implied. See SQLite's [atomic commit assumptions](https://sqlite.org/atomiccommit.html)
and the [File System Standard](https://fs.spec.whatwg.org/).
